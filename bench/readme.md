# Benchmarks

> This file is generated by `bun run bench all`. Do not edit it by hand.

Bun 1.4.4 and Node v26.12.1 on Apple M1 Max, 2026-10-27.

## Results

| Workload | Bun | Node |
| --- | --- | --- |
| `lint()`, 12 pages | 22.4ms | 31.3ms |
| `fs()`, a site of 1200 pages | 2.73s / 441MB | 3.75s / 832MB |

## Running

```sh
$ bun run build          # build seolint, which the benchmarks import
$ bun run bench build    # download missing pages and write the site
$ bun run bench all      # build, run on Bun and Node, then write this file
```

## Corpus

The corpus has 12 real pages, 4.78 MB in total:

- blog.cloudflare.com (198 kB)
- developer.mozilla.org_en-US_docs_Web_HTML_Element_a (226 kB)
- developer.mozilla.org_en-US_docs_Web_JavaScript_Reference_Global_Objects_Array (245 kB)
- docs.python.org_3_library_functions.html (331 kB)
- en.wikipedia.org_wiki_HTML (799 kB)
- en.wikipedia.org_wiki_Search_engine_optimization (388 kB)
- github.com_oven-sh_bun (511 kB)
- news.ycombinator.com (35 kB)
- www.apple.com (254 kB)
- www.bbc.com_news (390 kB)
- www.rust-lang.org (19 kB)
- www.theguardian.com_international (1.39 MB)

The site has 100 copies of each page, in its own folder, with a `robots.txt` and a `sitemap.xml` that lists every page. Their links are relative to the original sites, so most become internal links, which the site checks look for in the site folder.

## Method

- **`lint()`** lints every corpus page once per iteration with the default rules, timed by [mitata](https://github.com/evanwashere/mitata). Each iteration starts with a collected heap. This is the cost of the checks for one page, without the file system or the site checks.
- **`fs()`** lints the whole site in a fresh process, as the CLI does. It includes reading files and the site checks. The time is the median of 5 samples.
- **Memory** is the peak resident memory of the `fs()` process, as the median of 5 samples.
